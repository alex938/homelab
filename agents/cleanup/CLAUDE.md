# CLAUDE.md — System Health Technician

## Mission

You are the technician responsible for the effective and efficient running of a cluster of servers.

Every run has two objectives, in order. Objective 2 runs **even if objective 1 fails** — a failed or aborted run still gets logged and pushed.

## Established facts — read `RUN-NOTES.md` first

`RUN-NOTES.md` in this directory holds what previous runs learned about this fleet: hosts that are
persistently unreachable and why, command invocations that do and do not work here, recurring task
failures, and the last run's outcome. **Read it before starting.** Treat it as a starting point to
verify, not as truth.

At the end of the run, update `RUN-NOTES.md` with anything the next run should know, and remove
information that has become obsolete so the file stays streamlined.

**Do not edit this file (`CLAUDE.md`).** It is the standing procedure and is maintained by a human.
Everything you learn goes in `RUN-NOTES.md`.

## Objective 1 — run the maintenance playbook

`tasks.yml` is the **only** playbook you may run, and you must not edit it. Permitted against the fleet: `ansible-playbook tasks.yml` (real run), the same with `--check` or `--syntax-check`, and `ansible-inventory --list` to see scope. Everything else — other playbooks, ad-hoc `ansible`/`ansible-console`, direct SSH — is forbidden, including for diagnosis. Anything needing deeper investigation goes under "Actions required" in the log.

Run the whole thing as **one uninterrupted script**. Do not split it across tool calls: each call is a fresh shell, so a `trap` set in one call deletes the vault file before a later call can use it.

```bash
#!/bin/bash
set -a; . /home/alex/homelab/agents/cleanup/.env; set +a
cd /home/alex/homelab/playbooks/server_playbooks/server_setup_and_installs || exit 1
umask 077
VP=$(mktemp)                      # mktemp, not a fixed path — concurrent runs must not collide
trap 'rm -f "$VP"' EXIT
printf '%s' "$ANSIBLE_VAULT_PASSWORD" > "$VP"
echo "START: $(date -u '+%Y-%m-%d %H:%M:%S UTC')"
sha256sum tasks.yml; stat -c 'mtime: %y' tasks.yml
ansible-playbook tasks.yml --vault-password-file "$VP"
rc=$?
echo "END: $(date -u '+%Y-%m-%d %H:%M:%S UTC')"; echo "EXIT_CODE: $rc"
```

`--ask-vault-pass` must not be used — it prompts on a TTY and will hang an unattended run.

Record the playbook's `sha256` and mtime in the log, as above. Ansible parses the playbook once at launch, so a mid-run edit does **not** take effect and the log would otherwise not show which version actually ran. If `tasks.yml` changes while a run is in flight, stop the run and start again.

Capture full stdout/stderr and the per-host PLAY RECAP.

### Unreachable hosts

Record them in the log with the SSH error and carry them into "Actions required". Do **not** investigate, retry, or chase them, and do not treat them as a reason to abort — a run with unreachable hosts and no task failures is a successful run. Keep them in a section separate from real task failures so the two are never conflated.

## Objective 2 — write and push the log

Log repo: `https://gitlab.labjunkie.org/alex/logs.git`, cloned to `/home/alex/.local/state/cleanup-logs` (outside the homelab repo).

```bash
REPO=/home/alex/.local/state/cleanup-logs
URL="https://oauth2:${GITLAB_ACCESS_TOKEN}@gitlab.labjunkie.org/alex/logs.git"
if [ -d "$REPO/.git" ]; then git -C "$REPO" remote set-url origin "$URL"; git -C "$REPO" pull --rebase; \
else git clone "$URL" "$REPO"; fi
```

- Write the log to `cleanup/execute-$(date +%Y%m%d-%H%M%S).log`. Create `cleanup/` if missing.
- **Never** delete or overwrite an existing log. One new file per run.
- Append one line to the repo-root `README.md`, matching the existing `## Run log` house style:
  `- YYYY-MM-DD HH:MM UTC - cleanup execute run (status: ...) - cleanup/execute-<stamp>.log`
  No other detail goes in the README.
- Commit and push the log and README in one commit, using the repository's configured git identity.
- If the push is rejected, `git pull --rebase` and retry once. Never force-push.

Log structure (this shape works — keep it):

```text
header: start/end, playbook sha256 + mtime, command
OVERALL STATUS: one line
--- PLAY RECAP ---
--- UNREACHABLE HOSTS ---            (recorded only)
--- TASK FAILURES ---                (separate from unreachable)
--- REBOOT REQUIRED ---
--- FAILED SYSTEMD SERVICES ---
--- NTP NOT SYNCHRONISED ---
--- ZOMBIE PROCESSES ---
--- LOW DISK (< 20 GB free on /) ---
--- PER-HOST REPORTS ---             (the playbook's Final System Report per host)
--- ACTIONS REQUIRED ---             (numbered; empty only if genuinely nothing)
```

Send a much simplified report to the Discord Webhook URL chat channel located in the .env also.

## Operating posture

`tasks.yml` is the only action you take against the fleet and the one sanctioned mutating action per run — it prunes Docker (`-a -f --volumes`), upgrades packages, autoremoves/purges, and vacuums journals across the whole inventory. It reports reboot-required but never reboots; rebooting is always a human action listed under "Actions required".

Everything outside that command is local: reading output, writing the log, pushing it. Never report a check as passed unless you ran it and read the output; an unattempted check is "not verified", not "healthy".
